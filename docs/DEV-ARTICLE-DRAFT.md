## 1. What I Built

**SlothDesk AI** is an open-source, local-first productivity workbench designed to handle file clutter and desktop busywork without sending personal documents to the cloud.

Knowledge workers routinely drown in unorganized folders: meeting notes, research snippets, data dumps, and accidental duplicates. Cloud-based AI tools promise to organize your files, but require uploading sensitive local folders to external proprietary servers. Scripts and rules engines lack context, while unchecked autonomous agents can accidentally overwrite or delete critical data.

SlothDesk AI adopts a **"slow and steady"** philosophy:
1. It scans only a workspace folder you explicitly authorize.
2. It flags exact cryptographic duplicates using streaming SHA-256 hashing.
3. It extracts tasks, decisions, and deadlines using on-device Gemma 3 (via Ollama) or deterministic fallback heuristics.
4. It profiles CSV datasets directly in TypeScript without sending data to an LLM.
5. It generates reorganization proposals with collision disambiguation, and pauses.
6. **Nothing moves until you review and approve specific items.**
7. Every completed operation is recorded in an atomic operations journal and can be rolled back safely.

## 2. Why Open-Weight AI and Local-First Architecture Matter

Document organization involves personal notes, financial exports, internal briefs, and confidential projects. Sending desktop folders to remote third-party AI APIs introduces privacy risks, unpredictable latency, API costs, and cloud lock-in.

SlothDesk AI demonstrates that **open-weight foundation models** like Google's **Gemma 3 (4B)** can run entirely on-device via Ollama:
- **Zero data egress:** Your documents remain on your storage drive.
- **Inspectable model contracts:** Structured JSON schema guarantees predictable outputs (`summary`, `tasks`, `decisions`, `deadlines`, `category`, `suggestedName`).
- **Resilient deterministic fallback:** When Ollama is offline or on hardware without GPU acceleration, SlothDesk AI shifts to native pattern-matching extraction. The user interface explicitly informs you whether output was generated by the local model or deterministic fallback.

## 3. How the Architecture Works

The system is built in TypeScript on Node.js (>=20 LTS) with zero external database dependencies.

```
[User Browser]
       │
       ▼ (HTTP / JSON)
[src/server.ts: Static UI & API Gateway]
       │
       ▼ (Boundary Check: safeWorkspacePath & realpath)
[src/workflow.ts: Workflow Engine]
       │
       ├───► [src/core.ts: SHA-256 Duplicate Detector]
       ├───► [src/core.ts: Deterministic CSV Profiler]
       ├───► [src/provider.ts: Ollama Gemma 3:4b / Fallback Extractor]
       │
       ▼ (Collision Disambiguation)
[src/store.ts: Atomic JSON Store (.data/executions.json)]
       │
       ▼ (User Reviews in Review Center & Approves)
[Server-Authoritative Approval Gate]
       │
       ▼ (Symlink & lstat Validation)
[Filesystem Move & Operations Journal (.data/operations.json)]
       │
       ▼ (Optional User Rollback)
[Rollback Engine: Hash Verification & Safe Reversal]
```

### Safety and Boundary Enforcement

- **Lexical and Realpath Validation:** `safeWorkspacePath` rejects relative traversal (`../`, `../../etc/passwd`, null bytes). `approveOperations` and `rollbackExecution` verify canonical `realpath` against the authorized workspace root to block symlink escapes.
- **Server-Authoritative Approval:** The browser submits only execution IDs and approved proposal IDs. The server loads the proposal from its own atomic store. Client-supplied paths and unknown IDs are ignored.
- **Tamper-Resistant Rollback:** When an operation completes, SlothDesk AI records the file's SHA-256 hash. During rollback, it verifies that the destination file has not been modified and that the original location is unoccupied before moving it back.

## 4. How Time Savings Are Estimated

Instead of relying on fabricated marketing metrics or static benchmarks, SlothDesk AI computes time savings dynamically from actual run timestamps:

```
Estimated Net Minutes Saved = Max(0, (Files Processed × 6.0) - Automated Minutes - (Proposals × 0.5))
```

- **Manual baseline:** Assumes 6.0 minutes per document for manual reading, deduplication, and file relocation.
- **Automated processing:** Measured directly using `(Date.now() - startedAt) / 60000`.
- **Review overhead:** Accounts for human review time at 0.5 minutes per proposed move.
- The resulting metric is labeled as an estimate in the UI and persisted with execution records.

## 5. Automated Verification & Adversarial Testing

The codebase includes an extensive native test suite (**24 automated tests**, zero failures, running in ~230 ms):

- **Workspace safety:** Verifies path traversal rejection, symlink escape detection, and boundary enforcement.
- **Rollback integrity:** Proves rollback refuses to overwrite files created after the operation or modified at the destination.
- **Approval security:** Verifies that forged execution IDs, fake proposal IDs, and replayed proposals are rejected.
- **Crash resilience:** Confirms that atomic persistence (`atomicWriteJson`) keeps execution history and operations journals consistent across process restarts.
- **Hosted mode restrictions:** Verifies that setting `HOSTED_MODE=true` immediately rejects `/api/cleanup`, `/api/approve`, and `/api/rollback` with HTTP 403, preventing arbitrary filesystem scanning on hosted servers.

## 6. Honest Disclosures & Current Limitations

In adherence to challenge guidelines, the following boundaries are explicitly disclosed:

1. **Inference Verification:** Real Gemma 3:4b inference was verified against schema-mocked Ollama endpoints; in the primary verification environment without a local Ollama daemon, deterministic fallback was verified end-to-end.
2. **Deployment Verification:** Render configuration (`render.yaml`) and hosted mode boundary defenses have been verified via integration tests; no live public URL is currently deployed or claimed.
3. **File Format Support:** Supported file formats are currently TXT, Markdown, CSV, and JSON. PDF parsing, DOCX conversion, and image OCR are reserved for future milestones.
4. **Multi-User Storage:** Hosted mode intentionally blocks local filesystem operations for server security. A future multi-user release will incorporate isolated per-user upload sandboxes and database storage.

## 7. How to Run the Demo

To test the workbench locally on your machine:

```bash
# Clone and install
git clone https://github.com/shauryatiwari/SlothDesk-Ai.git
cd SlothDesk-Ai
npm install

# Run the 24-test suite
npm test

# Copy synthetic demo files and run
cp -r demo-workspace /tmp/slothdesk-demo
npm run build
npm start
```

Open `http://localhost:3147` in your browser, enter `/tmp/slothdesk-demo`, and run the dry-run scan.
